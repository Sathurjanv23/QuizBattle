# QuizBattle 2.0 Wire Protocol Specification

## 1. Transport & Framing Rules

- **Transport**: TCP stream (default port: `5000`)
- **Discovery**: UDP broadcast/listen (default port: `5001`)
- **Framing Delimiter**: Newline (`\n`, ASCII 0x0A)
- **Encoding**: UTF-8
- **Maximum Frame Size**: **65,536 bytes (64 KiB)**.
  - Sockets or channels that receive a line exceeding 64 KiB before a newline character MUST reject the frame, discard the buffer, and return an `ERROR` message.
- **TCP Stream Handling & Buffer Fragmentation**:
  - TCP is an arbitrary stream of bytes; a single `read()` call may deliver a partial JSON object or multiple concatenated JSON objects.
  - Implementations must buffer bytes until `\n` is encountered.
  - Once `\n` is found, the substring preceding `\n` is parsed as a single JSON message. The remaining bytes stay in the buffer for the next frame.

---

## 2. Protocol Envelope Format

Every message on the wire is a single-line JSON object:

```json
{"type":"<MESSAGE_TYPE>","requestId":"<OPTIONAL_UUID>","payload":{ ... }}
```

### Envelope Fields:
| Field | Type | Required | Description |
|---|---|---|---|
| `type` | String | **Yes** | Protocol event or command enum name (e.g. `CONNECT`, `QUESTION`). |
| `requestId` | String | *Optional* | Unique correlation identifier generated by sender for request-response pairing. |
| `payload` | Object | *Optional* | Structured data payload specific to the message `type`. |

---

## 3. Security Invariants

1. **Untrusted Client**: The client NEVER sends authoritative game data such as player scores or arbitrary target `playerId`.
2. **Session Association**: The server maps each socket connection to an internal `ClientSession`. On `CONNECT`, the server assigns/authenticates the player and stores this state in the session.
3. **Action Authorization**: When a client requests `CREATE_ROOM`, `JOIN_ROOM`, or `ANSWER`, the server derives the actor's identity solely from the socket's `ClientSession`.

## 4. Message Catalog & Payloads

### 4.1 Connection Lifecycle

#### `CONNECT` (Client -> Server)
Initiates handshake and requests session binding.
```json
{"type":"CONNECT","requestId":"req-1","payload":{"username":"CyberNinja"}}
```

#### `CONNECTED` (Server -> Client)
Confirms successful connection and assigns authoritative `playerId`.
```json
{"type":"CONNECTED","requestId":"req-1","payload":{"playerId":"usr-9481","username":"CyberNinja","protocolVersion":"2.0"}}
```

---

### 4.2 Room Management

#### `CREATE_ROOM` (Client -> Server)
Requests room creation.
```json
{"type":"CREATE_ROOM","requestId":"req-2","payload":{"roomName":"Java Masters","maxPlayers":4}}
```

#### `ROOM_CREATED` (Server -> Client)
```json
{"type":"ROOM_CREATED","requestId":"req-2","payload":{"roomId":"room-101","roomName":"Java Masters","maxPlayers":4,"hostPlayerId":"usr-9481"}}
```

#### `JOIN_ROOM` (Client -> Server)
```json
{"type":"JOIN_ROOM","requestId":"req-3","payload":{"roomId":"room-101"}}
```

#### `ROOM_JOINED` (Server -> Client)
```json
{"type":"ROOM_JOINED","requestId":"req-3","payload":{"roomId":"room-101","roomName":"Java Masters"}}
```

#### `ROOM_STATE` (Server -> Client Broadcast)
Broadcast to all room members whenever player joins, leaves, or readiness updates.
```json
{
  "type":"ROOM_STATE",
  "payload":{
    "roomId":"room-101",
    "roomName":"Java Masters",
    "hostPlayerId":"usr-9481",
    "state":"LOBBY",
    "players":[
      {"playerId":"usr-9481","username":"CyberNinja","score":0},
      {"playerId":"usr-3312","username":"PixelCoder","score":0}
    ]
  }
}
```

---

### 4.3 Quiz Flow

#### `START_QUIZ` (Client -> Server)
Must be issued by room host.
```json
{"type":"START_QUIZ","requestId":"req-4","payload":{"roomId":"room-101"}}
```

#### `QUESTION` (Server -> Client Broadcast)
Sent to all participants when a question begins. Notice: `correctOptionIndex` is omitted!
```json
{
  "type":"QUESTION",
  "payload":{
    "questionId":"q-101",
    "text":"What is the default port for QuizBattle TCP?",
    "options":["3000","5000","8080","9000"],
    "timeLimitSeconds":15,
    "pointValue":100
  }
}
```

#### `ANSWER` (Client -> Server)
Participant submits selected option.
```json
{
  "type":"ANSWER",
  "requestId":"req-5",
  "payload":{
    "questionId":"q-101",
    "selectedOptionIndex":1
  }
}
```

#### `ANSWER_RESULT` (Server -> Client)
Direct feedback to the answering participant.
```json
{
  "type":"ANSWER_RESULT",
  "requestId":"req-5",
  "payload":{
    "questionId":"q-101",
    "correct":true,
    "pointsAwarded":100,
    "currentTotalScore":100
  }
}
```

#### `QUESTION_CLOSED` (Server -> Client Broadcast)
Signals round end, reveals correct answer.
```json
{
  "type":"QUESTION_CLOSED",
  "payload":{
    "questionId":"q-101",
    "correctOptionIndex":1,
    "explanation":"TCP server defaults to port 5000."
  }
}
```

---

### 4.4 Standings & Game Termination

#### `LEADERBOARD` (Server -> Client Broadcast)
Broadcast after each question.
```json
{
  "type":"LEADERBOARD",
  "payload":{
    "roomId":"room-101",
    "standings":[
      {"rank":1,"playerId":"usr-9481","username":"CyberNinja","score":100,"correctCount":1},
      {"rank":2,"playerId":"usr-3312","username":"PixelCoder","score":0,"correctCount":0}
    ]
  }
}
```

#### `QUIZ_FINISHED` (Server -> Client Broadcast)
Final standings and winner announcement.
```json
{
  "type":"QUIZ_FINISHED",
  "payload":{
    "roomId":"room-101",
    "winnerPlayerId":"usr-9481",
    "standings":[
      {"rank":1,"playerId":"usr-9481","username":"CyberNinja","score":100,"correctCount":1},
      {"rank":2,"playerId":"usr-3312","username":"PixelCoder","score":0,"correctCount":0}
    ]
  }
}
```

---

### 4.5 System Diagnostics & Error Handling

#### `ERROR` (Server -> Client)
```json
{
  "type":"ERROR",
  "requestId":"req-2",
  "payload":{"code":"ROOM_FULL","message":"The requested room is at maximum capacity (4 players)"}
}
```

#### `PING` / `PONG`
Heartbeat check.
```json
{"type":"PING","requestId":"hb-1"}
{"type":"PONG","requestId":"hb-1"}
```
